### 1.2 Why Now?

1. **رقمنة المحاسبة**: ERP سحابي (Odoo/SAP/Zoho) صار متاحاً للشركات المتوسطة → البيانات جاهزة للربط للمرة الأولى.
2. **نضج المعايير**: AAOIFI (معيار الزكاة) ومعايير الهيئات الشرعية أصبحت مرجعاً مؤسسياً مستقراً.
3. **تنظيم زكوي متصاعد**: جهات زكوية حكومية تفرض إقرارات وصيغ تقارير → طلب على أدوات امتثال.
4. **LLMs**: صارت قادرة على الاستخراج والتفسير — لكنها غير مؤهلة للإفتاء، وهذه بالضبط هي الفجوة المعمارية التي نملؤها (AI فوق Rules Engine لا بدلاً منه).
5. **غياب لاعب مؤسسي**: السوق كله حاسبات مجانية وتطبيقات خيرية. لا يوجد "Zakat Infrastructure".

### 2.2 حجم الفرصة (منهجية، لا أرقام مُختلقة)

لا أدّعي أرقام TAM محددة دون مصدر. الطريقة المعتمدة للتقدير عند إعداد ملف الاستثمار:

```
TAM  = (عدد المنشآت المسجلة في الأسواق المستهدفة × متوسط ثمن اشتراك B2B)
     + (عدد المكلفين الأفراد ذوي الأصول فوق النصاب × ARPU)
SAM  = ما يمكن الوصول إليه لغوياً وتنظيمياً (عربي/إنجليزي، 6 أسواق أولى)
SOM  = 1–3% من SAM خلال 36 شهراً
```
المصادر المطلوب سحبها فعلياً قبل العرض: سجلات الغرف التجارية، تقارير الهيئات الزكوية الرسمية، تقارير صناعة التمويل الإسلامي السنوية.

## 7. Corporate Zakat Architecture

### 7.1 التدفق

```
Company Profile → Accounting Period → Import (TB/BS)
 → Accounting Mapping (COA)
 → Zakat Classification (10 فئات)
 → Shariah Treatment (قاعدة + مصدر)
 → Zakat Base
 → Nisab Check → Rate (2.5% هجري / 2.577% ميلادي)
 → Zakat Due → Review → Report + Certificate
```

### 7.2 التصنيف الزكوي (مطبّق فعلياً في `src/lib/erp/zakatMapping.ts`)

| الفئة | زكوي | يُخصم |
|---|---|---|
| cash — نقد وما في حكمه | ✓ | — |
| receivables — ذمم مرجوّة | ✓ | — |
| inventory — عروض تجارة | ✓ | — |
| investments — استثمارات متاجرة | ✓ | — |
| fixed_assets — أصول ثابتة | ✗ | — |
| prepayments — مدفوعات مقدمة | ✗ | — |
| current_liabilities | ✗ | ✓ |
| long_term_liabilities | ✗ | ✗ (إلا القسط المستحق خلال الحول) |
| equity | ✗ | ✗ |
| excluded | ✗ | ✗ |

**قاعدة الحساب** (صافي الأصول المتداولة):
```
Base = (Cash + Receivables + Inventory + Trading Investments)
     − (Current Liabilities due within the Hawl)
Due  = Base × Rate   إذا Base ≥ Nisab
```

**طبقات التصنيف** (بالأولوية): تجاوز يدوي → قاعدة المزوّد (Odoo `account_type` / نطاقات أكواد SAP) → كلمات مفتاحية عربي/إنجليزي → `excluded` افتراضاً.

### 7.3 منهجيات بديلة (Configurable — لا نفرض واحدة)

| المنهجية | الصيغة | متى تُستخدم |
|---|---|---|
| صافي الأصول المتداولة (Net Current Assets) | كما أعلاه | الافتراضية، الأشيع مؤسسياً |
| صافي الموجودات (Net Assets / رأس المال العامل) | حقوق الملكية + التزامات طويلة − أصول ثابتة − خسائر مرحّلة | تُختار من إعدادات الشركة |
| الوعاء المعدّل حسب الجهة التنظيمية | صيغة قُطرية | Country Engine |

كل شركة تختار منهجية، وتُختم في التقرير باسمها ونسختها.

## 8. Shariah Rules Engine

### 8.1 مبدأ التصميم
قواعد مُعرَّفة بيانياً (declarative)، مُصدَّرة، مُصدَقة بشرياً، ومُصدَّرة بإصدارات — **لا استدلال حر من نموذج**.

### 8.2 مخطط القاعدة

```ts
interface ZakatRule {
  ruleId: string;            // ZR-GOLD-JEWELRY-001
  name: string;
  description: string;
  assetType: AssetType;
  zakatStatus: 'zakatable' | 'exempt' | 'conditional' | 'deductible';
  conditions: Condition[];   // قابلة للتقييم آلياً
  exceptions: Exception[];
  madhab: Madhab | 'agreed';
  methodology: string;
  source: { type:'quran'|'sunnah'|'fiqh'|'academy'|'standard'|'fatwa'; citation: string; url?: string };
  reference: string;
  divergence?: { view: string; madhab: Madhab; source: string; impact: string }[];
  requiresHumanReview: boolean;
  effectiveDate: string; reviewDate: string;
  reviewer: string; version: string;
}
```

### 8.3 آلية التنفيذ
```
Input Facts → Rule Matching (assetType + madhab + conditions)
 → Conflict Resolution (specificity > madhab-preference > default)
 → Treatment
 → Explanation Node (input, rule, source, math)
```
عند تعدد الأقوال المعتبرة: يُطبَّق قول المنهج المختار، **وتُعرض** الأقوال الأخرى مع أثرها الرقمي على النتيجة، وتُرفع المسألة للمراجعة البشرية إن كان `requiresHumanReview`.

## 9. المذاهب والمناهج

مدعومة: **حنفي · مالكي · شافعي · حنبلي** + منافذ إضافة مناهج معاصرة (قرارات مجامع / معايير مؤسسية).

قاعدة العرض عند الخلاف:
1. الحكم وفق المنهج المختار.
2. الأقوال الأخرى المعتبرة.
3. مصدر كل قول.
4. **الأثر الرقمي**: "لو اخترت القول الآخر، تصبح الزكاة X بدل Y".
5. تنبيه بالحاجة إلى فتوى/مراجعة عند التعقيد.

أمثلة مسائل خلافية تُدار بهذا النمط (لا نرجّح فيها من عندنا): حلي النساء المستعمل · خصم الديون طويلة الأجل · زكاة المستغلات · تقييم المخزون (تكلفة/سوق) · زكاة الأسهم غير المتداولة · الأصول الرقمية.

## 60–61. User Stories & Acceptance Criteria

> As a Muslim individual, I want to calculate my zakat based on my selected methodology so that I can understand exactly how much I owe and why.
> - **Given** اخترتُ مذهباً وأدخلتُ أصولي وخصومي
> - **When** أضغط "احسب"
> - **Then** أرى الوعاء والمستحق، وبجانب كل بند زر "لماذا؟" يعرض القاعدة ومصدرها ونسخة المحرك.

> As a company accountant, I want to upload a trial balance and get a zakat base so that I can prepare the declaration without manual reclassification.
> - **Given** ملف ميزان مراجعة صحيح
> - **When** أرفعه وأعتمد التصنيف
> - **Then** يُنتَج وعاء وزكاة مستحقة مع ورقة عمل، وتُدرَج الحسابات غير المصنّفة في قائمة استثناءات.

> As a Shariah reviewer, I want to approve or override a treatment with a mandatory reason so that the decision is auditable.
> - **Given** حالة معلّقة
> - **When** أعتمد أو أتجاوز
> - **Then** يُسجَّل القرار والسبب والهوية والوقت، ولا يمكن حذفه.

> As an individual, I want my archived report to stay identical after a rules update so that my records are reproducible.
> - **Given** تقرير 2026 مؤرشف
> - **When** تُحدَّث القواعد أو الأسعار
> - **Then** يظل التقرير القديم ونتائجه كما هي بنسختها المثبّتة.

## 67. Design System

- **الألوان**: أخضر عميق مؤسسي (لا أخضر خيري فاقع) + ذهبي مُطفأ للتمييز + رمادي محايد للأسطح + أحمر/كهرماني للحالات. سيمانتيك tokens حصراً، دعم داكن كامل.
- **الخطوط**: عربي — خط عربي هندسي واضح للأرقام (تفضيل خطوط بأرقام tabular)؛ إنجليزي — sans هندسي. **ممنوع** Inter/Poppins الافتراضية والتدرجات البنفسجية.
- **الأيقونات**: خطية رفيعة موحدة السماكة.
- **Dashboard**: بطاقات KPI + مخططات هادئة + جداول كثيفة المعلومات.
- **التقارير**: طباعة رسمية، ترويسة/تذييل ثابت، أرقام مُحاذاة، لا زخرفة.
- **المخططات**: ألوان الفئات ثابتة عبر المنتج (نقد/ذهب/أسهم/عروض/عقار).
- **عرض المصادر**: بطاقة اقتباس منفصلة بخلفية محايدة + معرّف القاعدة + رابط المصدر.
- **الهوية**: Modern Islamic FinTech — لا جمالية جمعية خيرية.
