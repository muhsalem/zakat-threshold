# نِصاب — سطح المكتب (Tauri)

غلاف Tauri رفيع حول نفس واجهة الويب. لا يُكرَّر أي منطق حساب زكاة أو
فتوى هنا — كل ذلك يبقى في `src/` (كود الويب نفسه)، والنافذة هنا فقط
تعرضه.

## قبل أول تشغيل

1. **ثبّت Rust** (مطلوب لبناء الغلاف الأصلي): https://rustup.rs
   تحقق: `cargo --version`
2. **استبدل الرابط المؤقت** في `tauri.conf.json` (كل من `build.frontendDist`
   و`app.windows[0].url`) بدومين نِصاب المنشور فعلياً بدل
   `https://REPLACE-WITH-YOUR-DEPLOYED-DOMAIN.example`.
3. **الأيقونات**: `bundle.icon` يشير لملفات PNG/ICO/ICNS غير موجودة بعد
   (المتاح حالياً `public/icon-192.svg` فقط، وTauri يحتاج صيغاً مرسومة
   نقطياً لا SVG). ولّدها من الشعار الحالي عبر:
   ```
   bunx tauri icon public/icon-512.svg
   ```
   (يُنشئ مجلد `src-tauri/icons/` تلقائياً بكل المقاسات المطلوبة.)

## التشغيل

- **تطوير محلي** (يحتاج `bun run dev` شغّالاً في نافذة أخرى بالتوازي):
  ```
  bun run tauri:dev
  ```
- **بناء نسخة قابلة للتوزيع** (exe/msi على ويندوز، dmg على ماك، AppImage/deb على لينكس):
  ```
  bun run tauri:build
  ```

## القرار المعماري: لماذا رابط بعيد لا حزمة ثابتة؟

المنصة تعتمد بكثافة على دوال خادم حقيقية (createServerFn) لا يمكن
تجميدها كملفات ثابتة: مزامنة ERP، استخراج الذكاء الاصطناعي، الدفع عبر
Stripe، وطابور المراجعة البشرية. لذلك اختير نمط "غلاف حول رابط مستضاف"
بدل تصدير ثابت (`vite build` + `frontendDist` محلي) — يحافظ على كل
الميزات دون إعادة بناء سيرفر Node كامل داخل الحزمة. يبقى الاتصال
بالإنترنت مطلوباً لهذه الميزات بغض النظر عن المنصة، تماماً كنسخة الويب.
